## The project: vegetation proximity risk map for power lines

A Dagster pipeline that turns public data into a risk map per power-line segment.
Pilot area: Morbihan (France), partitioned by municipality or grid square.

Thoses target can be redefined during the project

### Target asset graph

1. `osm_power_lines`: `power=line` features from OpenStreetMap (Geofabrik or Overpass), cleaned, stored as GeoParquet.
2. `line_segments`: lines split into ~100 m segments with deterministic IDs.
3. `corridor_buffers`: buffers around segments (e.g. 15 m and 30 m).
4. `canopy_height_tiles`: public canopy height tiles (Meta/WRI on AWS Open Data), read by window (COG) without downloading everything.
5. `segment_vegetation_stats`: per segment, max height, mean height, share of area above a height threshold.
6. `segment_risk_score`: simple, explainable score.
7. `risk_map`: GeoPackage export openable in QGIS, plus a small web map.

### Dagster requirements

- Partitions by geographic area; adding a territory means adding a partition.
- **Idempotency**: rerunning a partition gives the same result; atomic writes (temp file, then rename).
- **Asset checks**: no segment with missing values, valid geometries, plausible heights (0-80 m), complete tile coverage.
- Demonstrable **backfill**: changing the threshold or scoring method recomputes only assets 5-7.
- At least one **sensor** (e.g. new OSM data update).
- Asset metadata (segment count, median height, duration) visible in the UI.
- pytest tests for business logic, independent of Dagster.

### Geospatial requirements

- Work in Lambert-93 (EPSG:2154) for distances; WGS84 only for data exchange.
- Document data limitations (OSM quality, canopy resolution, data date).
- Explain each spatial operation (reprojection, buffer, zonal statistics) when first introduced.
